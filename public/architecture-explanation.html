System Components

The system is comprised of four primary components working in coordination over secure web interfaces:

  • Webhook Listener: app/api/telegram/webhook/route.ts handles authentication and runs actions asynchronously.
  • Pending State Store: lib/telegram-pending.ts holds intermediate JSON state in Supabase (or fallback file system) with a 15-minute TTL.
  • AI Parser: lib/parse.ts connects to Groq using tool-calling to extract parameters into typed data.
  • Action Handler: lib/actions.ts validates, normalizes, and saves completed entries to the database.

Before vs. Now: How Correction Works

Previously, any modification to a pending action was parsed completely from scratch, leading to state loss. Now, the system uses the pending action as a template for contextual refinement.

✗ BEFORE: No-Context Parsing
1. Initial Message: "sent 1000 to Priyanka"
➔ Webhook creates a pending spending action.
2. User Correction: "description should be sent money to sis"
➔ Webhook receives the correction but passes no pending action context to the parser.
3. Result: Parser evaluates the correction in isolation. Because of the phrase "should be", the LLM misinterprets the input as a todo task: 
{
  "type": "task",
  "data": { "title": "sent money to sis" }
}
⚠️ The original ₹1000 spend log is overwritten and completely lost.
✓ NOW: Context-Aware Updates
1. Initial Message: "sent 1000 to Priyanka"
➔ Webhook creates a pending spending action.
2. User Correction: "description should be sent money to sis"
➔ Webhook detects the active spending action and passes it to the parser as the pendingAction parameter.
3. Result: The LLM uses the pending action as a template. It maps "description" to the item field and updates it while preserving all other fields (amount, category, etc.): 
{
  "type": "spending",
  "data": {
    "item": "sent money to sis",
    "amount": 1000,
    "category": "Other"
  }
}
✓ The pending action is updated in place, retaining the ₹1000 amount!
The Natural Language Correction Engine

Unlike a standard one-shot parser, our system stores the active pending action as a structured JSON object. When the user responds, if there is a pending action, the system loads it from the database/file system and passes it directly to the AI model as historical context.

lib/parse.ts (How context is injected) TypeScript 
if (pendingAction) {
  messages.push({
    role: "system",
    content: `Active Pending Action (awaiting user confirmation):
${JSON.stringify(pendingAction, null, 2)}

The user's input might be a correction, refinement, or modification to the fields of this active pending action (e.g., changing the amount, description/item/title, category, time, etc.).
If the user's input is correcting or adjusting the pending action, you MUST output an updated version of the action (call the appropriate tool with the updated fields, preserving any unchanged fields from the pending action).
If the user's input is a completely new command, ignore the pending action and parse the input as a new action normally.`
  });
}
