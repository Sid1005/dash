Architecture Upgrade

AI Telegram Parser V2

Migration from Custom Prompts to Single-Stage Groq gpt-oss-120b Tool Calling
The Problem (Why It Failed)

Previously, logging inputs like "spent 1800 on a cab from hyd to blr" incorrectly fell back to general chat notes instead of categorizing them as spending.

  • Reasoning Token Truncation: The classification model used `deepseek-v4-flash` (a reasoning model). With `max_tokens` set to only 128, the thinking tokens consumed the entire budget. The actual content response came back empty (`""`), triggering a JSON parse error.
  • Double LLM Calls: Every user message went through 2 API calls: Classification first, then Parsing. This doubled prompt processing latency and cost.
  • Monolithic Prompt: 100+ lines of raw rules and regular expression wrappers inside the code trying to coerce the LLM to write clean JSON.
The Solution (Tool Calling)

We completely restructured the system using Groq's high-capacity open-source gpt-oss-120b model combined with native Tool Calling.

  • Single LLM Call: The model directly decides which logging tool to trigger and supplies structured arguments in one single pass.
  • Zero Custom Regex Parsing: The JSON schema is enforced at the API layer. Argument structures are guaranteed.
  • Improved Latency & Cost: By reducing LLM runs from 2 to 1 and offloading classification to the tool router, the parser is twice as fast.

How It Works Under the Hood
1

Message Received

The Telegram Webhook forwards natural language input (e.g. "spent 1800 on a cab") with the current IST timestamp.

2

Groq Tool Completion

Groq's openai/gpt-oss-120b is invoked with a single system prompt + 11 distinct tool schemas (representing workout, spending, food, calendar blocks, tasks, notes, etc.).

3

Tool Call Dispatched

The model returns a tool_calls array. The matching tool executes and formats the response for the Telegram UI preview buttons.
