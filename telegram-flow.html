What happens when you send "gym 5:15 to 6:15"

A complete trace through the Telegram → webhook → AI parse → Supabase pipeline

gym 5:15 to 6:15
You, via Telegram
The flow
1
Telegram
Bot API delivers your message
Telegram's Bot API sends a POST to your registered webhook URL. The payload includes your user_id, chat_id, and the raw text "gym 5:15 to 6:15".
POST https://your-app.vercel.app/api/telegram/webhook x-telegram-bot-api-secret-token: <TELEGRAM_WEBHOOK_SECRET> { "message": { "from": { "id": 123456789 }, "chat": { "id": 123456789 }, "text": "gym 5:15 to 6:15" } }
2
Webhook handler · app/api/telegram/webhook/route.ts
Auth check + instant 200
The Next.js route handler runs two guards immediately:

1 Secret token in the header must match TELEGRAM_WEBHOOK_SECRET.
2 Your user_id must be in TELEGRAM_ALLOWED_USER_IDS.

If both pass, the route calls after() to schedule the real work and returns 200 OK to Telegram right now — Telegram needs a fast ack or it retries. The heavy lifting (AI parse + DB write) runs asynchronously after the response is sent.
3
AI Parse · lib/parse.ts → OpenCode AI / DeepSeek v4-flash
Natural language → structured JSON
parseNaturalLanguage() calls DeepSeek v4-flash (via the OpenCode AI OpenAI-compatible endpoint) with a detailed system prompt that knows all your data types.

The prompt includes disambiguation rules like:
"Use time_block whenever the input has a time range… gym/run/walk → Health"

Your message "gym 5:15 to 6:15" gets parsed as:
{ "type": "time_block", "data": { "start": "17:15", "end": "18:15", "activity": "Gym", "category": "Health" } }
Note the AM/PM disambiguation: the current time is ~17:xx, so bare "5:15" is resolved to 17:15 (PM), not 05:15 AM.
4
Pending store · lib/telegram-pending.ts → Supabase
Parsed action is held, waiting for your confirmation
The parsed action is NOT saved yet. It's written to the telegram_pending Supabase table, keyed by your chat_id, with a 15-minute TTL. This lets the bot ask "did I get this right?" before committing anything.

5
Telegram Bot API · sendTelegramMessageWithButtons
Bot sends you a confirmation message with inline buttons
formatActionPreview() formats the parsed result into readable text, and sendTelegramMessageWithButtons() sends it back with two inline keyboard buttons.
Telegram bot reply
I parsed a time block: 17:15-18:15 for Gym.
Note it down? Reply yes or no.
Yes, note it
No
6
You
You tap "Yes, note it"
Telegram sends a callback_query to the webhook (same endpoint, different body shape). The webhook routes it to processCallbackQuery(), which reads callback_data: "confirm_yes".
{ "callback_query": { "data": "confirm_yes", "from": { "id": 123456789 }, "message": { "chat": { "id": 123456789 } } } }
7
Supabase · time_blocks table
Time block is written to the database
applyParsedAction() in lib/actions.ts handles the "time_block" type. It calls insertTimeBlock(date, block) in lib/time-blocks-supabase.ts, which validates the times and inserts a row.

8
Telegram
Bot confirms. Done.
sendTelegramMessage() fires one last message back to your chat.
Telegram bot reply
✓ Logged 17:15–18:15: Gym
The block is now visible in your dashboard's Today view (TimeBlockGrid component) the next time the page loads or refreshes.
If you had sent "no" instead
clearPending(chatId) is called, the row in telegram_pending is deleted, and the bot replies "Okay, not saved." — nothing hits the time_blocks table. The 15-minute TTL on the pending record means it expires automatically even if you ignore the message.
What if it expired (15 min passed)?
getPending() checks created_at. If more than 15 minutes have passed, it deletes the stale row and returns null. The bot replies "No pending item to save. Send a new message first."
